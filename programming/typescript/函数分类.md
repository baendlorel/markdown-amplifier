# JS/TS 函数行为研究

_2025-05-01 煤球作_

TS/JS 的函数行为多样，在制作 npm 包 js-is-arrow-function 的过程中，我进行了一系列研究，分享结论如下

# ECMA262 规范中的一些内容

1. 函数具有内部方法`[[Call]]`，使其可以被调用。须知没有此属性的对象，就算使用代理拦截`apply`也不行。
2. 可能会具有内部方法`[[Construct]]`，这样就可以用作构造函数。理论上具备`[[Construct]]`的前提是拥有`[[Call]]`，但我们无法接触到这些属性，故对我们来说这总是成立的。
3. 内部方法`IsCallable`用于判断是否具有`[[Call]]`属性，`IsConstructor`同理
4. 函数具有`length`属性，代表了所有不具有默认值的参数的个数

# 具体分类

尽管函数们不一定有`prototype`属性，但它们总是`Function`的实例，有如下表达式为真

```typescript
fn instanceof Function; // true for all functions
```

## 普通函数

### 定义

普通函数就是使用`function`关键字定义的函数，一般像下面这样写

```typescript
function fn() {
  // 函数体
}
```

此类函数可以用作**构造函数**，即`new fn()`这样使用，也可以直接调用，是初学接触的最简单形式的函数 \
一般我们正常写代码的话，这样的函数不会是匿名的。比如下面的写法：

```typescript
a = function () {}; // a.name === 'a'
```

，函数名称会被设定为`a`。\
然而，如果我们采取一些另类的写法，将可以定义出匿名的函数

```typescript
a = (() => function () {})(); // a.name === ''
```

在 nodejs 环境下会表现为`[Function (anonymous)]`，浏览器中则直接是`function () {}`。\

### 特征

1. 具有`arguments`、`super`、`new`、`prototype`
2. 调用`toString()`会显示和定义的时候完全一样的文本，包括注释、空格、换行

### `this`指向

普通函数可以绑定`this`

1. 如果全局调用此函数，那么`this`会指向`window`或者`global`
2. 如果是`new fn()` 调用的，那么`this`会指向新生成的对象
3. 如果是`bind`、`call`、`apply`绑定了，那么会指向绑定好的值
4. 如果是`someHtmlElement.addEventListener`里用到这种函数，则 `this` 会指向这个`someHtmlElement`
5. 成员函数会指向类实例，这会在下方提到

## 箭头函数

为了解决函数二义性而在 ES6（ECMAScript 6， 2015 年发布）中提出的。

### 定义

```typescript
const fn = () => {}; // fn.name === 'fn'
```

### 特征

1. 不具有`arguments`、`super`、`new`、`prototype`
2. 不可以用作构造函数，会发生`TypeError`
3. 同普通函数，调用`toString()`会显示和定义的时候完全一样的文本，包括注释、空格、换行

### `this`指向

箭头函数无法绑定`this`，所有与之相关的操作均无效，其指向在声明时就已经由其所在上下文决定

## 成员函数

类实例中的函数，可以是静态的或者非静态的

### 定义

```typescript
class A {
  fn() {}
}
```

### 特征

1. 具有`arguments`，没有`super`、`new`、`prototype`
2. 不可以用作构造函数，会发生`TypeError`
3. 调用`toString()`会显示和定义的时候完全一样的文本，包括注释、空格、换行。但略有区别，具体如下：

```typescript
instance.fn.toString() === 'fn() {}'; // true
instance.fn.toString() !== 'function fn() {}';
```

5. 如果成员函数的名称使用`Symbol`的话，那么`toString()`的行为会有所变化，具体如下：

```typescript
const sym = Symbol('fn');
class A {
  [sym]() {}
  [Symbol.for('fn')]() {}
}
const instance = new A();

// 普通Symbol会展示为变量名，全局Symbol会展示整个定义
instance[sym].toString() === '[sym]() {}';
instance[Symbol.for('fn')].toString() === `[Symbol.for('fn')]() {}`;

// 函数名均为Symbol里面的内容加上方括号
instance[sym].name === '[fn]';
instance[Symbol.for('fn')].name === '[fn]'; // 两者一样

// 若此时有一个函数是：
const otherFn = { '[fn]': function () {} }['[fn]'];
otherFn.name === '[fn]'; // 将和上面的名字无法区分
```

### `this`指向

1. `this`指向类实例
2. 可以绑定别的`this`，有如下代码成立

```typescript
class A {
  fn() {
    return this.name;
  }
}
const a = new A();
a.fn() === undefined; // true
const bindedFn = a.fn.bind({ name: 'Alice' });
bindedFn() === 'Alice'; // true
```

## 绑定函数

由`fn.bind`（内部对应的方法是`BoundFunctionCreate`）创建出来的新函数

### 定义

```typescript
const binded = fn.bind(someObject);
```

### 特征

1. 原来的函数有啥它就有啥
2. 能否用作构造函数取决于原函数可不可以
3. 调用`toString()`不会显示原函数，而是如下的样子

```typescript
binded.toString() === 'function () { [native code] }';
```

4. 绑定函数的`name`属性是`bound fn`，即`bound 原函数名`（可能在某些很老的浏览器中不是这样，但现代浏览器和 nodejs 都是这样的），比如

```typescript
binded.name === 'bound fn'; // true
```

5. 无论原来是否为箭头函数，绑定后统一都是这个样子，会失去箭头函数、成员函数的`toString`特征
6. 实际上绑定函数具有内部属性`[[BoundTargetFunction]]`，且会被`[[Call]]`调用，可惜我们看不到，也因此我们无法获知函数绑定前的样子

## 异步函数

定义的时候前面加了`async`的函数，本身可能属于普通、箭头、成员函数的一种。

### 特征

1. 所有的异步函数都不可以作为构造函数使用，会有`TypeError`
2. 异步函数`bind`后再`toString()`会失去`async`字样，变成统一的样子，无法识别
3. 需注意，返回`Promise`对象的函数并不一定是异步函数，异步函数返回值一定是`Promise`

# 总结

本文将 TS/JS 中的函数分了五类：普通函数(具有完整特性可作构造器)、箭头函数(无自身 this 和 prototype)、成员函数(类中的方法)、绑定函数(通过 bind 创建)和异步函数(async 关键字)。它们在 this 指向、构造器能力、toString()行为和特有属性上有明显差异，理解这些差异对于避免常见的"this 指向"问题和函数使用错误具有重要意义，甚至可以揭示某些公共库中函数的异常行为。
